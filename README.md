# Chain Health Monitor

External synthetic monitoring for blockchains, built the way an SRE team would monitor any critical third-party dependency.

It probes five public chains (Ethereum, Base, Arbitrum, Polygon, Solana) through **two independent RPC providers each**. Having two providers per chain lets it answer the question that matters during an incident:

> **Is the chain down, or is just one of our providers down?**

- **Every provider goes stale together** → the chain itself has probably halted (critical alert).
- **One provider falls behind or errors** → it's a provider problem. Fail over, don't panic (warning).
- **Every provider fails at once** → *we* are blind (our network, DNS or egress). Say so instead of guessing.

A sixth fake chain, `demo`, can be broken on purpose so you can show an incident live.

## Architecture

```
                    ┌──────────── RPC provider A ─┐
 chain-health-  ───►│                             ├─ Ethereum / Base / Arbitrum / Polygon / Solana
 exporter (Python)  └──────────── RPC provider B ─┘
     │  /metrics                     mock-rpc (fake "demo" chain you can break)
     │  JSON logs
     ▼                 ▼
 Prometheus ──rules──► Alertmanager (inhibits provider alerts during a chain halt)
     │               Loki ◄── Alloy (log shipper)
     └────────► Grafana ◄───┘   one dashboard: freshness, lag, latency, SLOs, events
```

| Piece | What it does |
|---|---|
| `exporter/app.py` | Probes every chain/provider every 10s. Exports head block, block timestamp, success, latency histogram, and error counters. Logs JSON events when a provider falls behind or recovers. |
| `prometheus/rules.yml` | Recording rules (head age, provider lag, SLIs) and alerts, including multiwindow SLO burn-rate alerts. |
| `prometheus/rules_test.yml` | `promtool` unit tests that prove the alerts can tell a chain halt from a provider problem. |
| `dashboards/chain-health.json` | Grafana dashboard, generated by `scripts/build_dashboard.py`. |
| `deploy/compose/` | Full local stack with Docker Compose. |
| `deploy/k8s/` | Kubernetes manifests and Helm values (kube-prometheus-stack, Loki, Alloy). |
| `.github/workflows/ci.yml` | Lint, rule unit tests, smoke test, then builds and pushes the image to GHCR. |

## SLOs

| SLO | SLI | Target (30 days) | Alerting |
|---|---|---|---|
| Chain freshness | Newest block on the best provider is younger than `max(10 × block time, 60s)` | 99.9% of the time | `ChainHeadStale`, `ChainHeightNotAdvancing` |
| Provider availability | Successful probes ÷ all probes, per provider | 99% (1% error budget) | Fast burn: 14.4× over 1h *and* 5m (page). Slow burn: 6× over 6h *and* 30m (ticket) |

The burn-rate thresholds follow the Google SRE Workbook's multiwindow approach. The long window proves the problem is real, and the short window proves it's still happening, so the alert resolves quickly after recovery.

## Run it locally (Docker)

```bash
./scripts/check-endpoints.sh                 # every RPC URL should print OK
cd deploy/compose && docker compose up -d --build
```

- Grafana: http://localhost:3000 (the dashboard is the home page; anonymous viewing is on)
- Prometheus: http://localhost:9090/alerts
- Alertmanager: http://localhost:9093

**Check it worked:**
1. Prometheus → Status → Targets shows `chainmon` as **UP**.
2. The dashboard's "Chain freshness" panel shows every chain in green within about a minute.
3. Grafana → Explore → Loki: `{app="chain-health-exporter"}` returns JSON log lines.

**Break something:**
```bash
curl "localhost:8545/control?provider=bravo&mode=lag"   # one provider falls behind -> ProviderBehind in ~5 min
curl "localhost:8545/control?chain=halt"                # whole chain stops -> ChainHeadStale in ~3–4 min
curl "localhost:8545/control?chain=run"                 # recover
curl "localhost:8545/control?provider=bravo&mode=ok"
```

## Run it on Kubernetes (Linode LKE)

Size: kube-prometheus-stack plus Loki needs about 3 GB of RAM. Two 4 GB nodes is comfortable.

1. Push this repo to GitHub. CI builds `ghcr.io/<you>/chain-health-exporter`. In GitHub → Packages, set the package to **public**, or the cluster can't pull it.
2. Download the LKE kubeconfig and check `kubectl get nodes`.
3. Deploy:
   ```bash
   IMAGE=ghcr.io/<you>/chain-health-exporter:latest ./scripts/k8s-deploy.sh
   ./scripts/verify-k8s.sh           # each layer prints PASS/FAIL, in order
   kubectl -n monitoring port-forward svc/kps-grafana 3000:80
   ```
4. For a public link, uncomment the `service: type: LoadBalancer` block for Grafana in `deploy/k8s/values-kube-prometheus-stack.yaml`, re-run the deploy, then `kubectl -n monitoring get svc kps-grafana`. **Change `adminPassword` first.**

## Tests (no Docker or cluster needed)

```bash
pip install -r exporter/requirements.txt
./scripts/smoke-test.sh                          # fake chain + exporter, breaks a provider, checks detection
promtool check rules prometheus/rules.yml
promtool test rules prometheus/rules_test.yml    # halt vs provider-behind vs blind
```

## What I'd add next

- Probes from several regions (one exporter per region), to separate a regional network problem from a provider problem.
- Synthetic transactions: send a real transaction and measure time to inclusion, not just whether reads work.
- Finality tracking (`safe`/`finalized` block tags on Ethereum and L2s).
- High-availability Prometheus and Alertmanager, plus long-term storage (Thanos or Mimir).
